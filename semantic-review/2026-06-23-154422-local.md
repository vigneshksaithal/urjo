# Removal of speed_window growth post slot

The `speed_window` slot — an 8am UTC scheduler run that posted a "set the fastest solve" puzzle — has been excised from the growth machinery. The cron schedule drops the 8am fire, `GrowthPostSlot` loses the variant, `getGrowthPostSlot` removes the hour-8 branch, `buildGrowthPostTitle` drops the matching title, and tests are updated or deleted accordingly. The change is tightly scoped and the diff is internally consistent.

**Watch for:** `PostFrequency` still carries `'twice_daily'` as a valid value, but after this change it behaves identically to `'once_daily'` — confirmed dead value.

---

## High-level view

The three-slot scheduling model (speed_window at 08:00, daily_puzzle at 16:00, evening_puzzle at 23:00) is now a two-slot model (daily_puzzle at 16:00, evening_puzzle at 23:00). All code paths involving the removed slot are cleanly eliminated: the cron entry, the slot type, the slot classifier, the title formatter, and the tests.

The `PostFrequency` union in `growth-types.ts` still includes `'twice_daily'`. Before this change, `twice_daily` meant "daily_puzzle + speed_window". After it, `isGrowthPostSlotEnabled` returns `true` for `daily_puzzle` regardless of frequency, and `false` for `evening_puzzle` unless `thrice_daily`. So `twice_daily` and `once_daily` now produce exactly the same scheduling behavior. The default config in `subreddit-config.ts` still seeds new installs with `postFrequency: 'twice_daily'`, which will silently behave like `once_daily`.

### `twice_daily` is now a dead frequency value

`isGrowthPostSlotEnabled` after this change:

```typescript
export const isGrowthPostSlotEnabled = (
    frequency: PostFrequency,
    slot: GrowthPostSlot,
): boolean => {
    if (slot === 'daily_puzzle') return true
    if (frequency === 'thrice_daily') return true
    return false
}
```

`GrowthPostSlot` is now `'daily_puzzle' | 'evening_puzzle'`. The only path reaching `return false` is `evening_puzzle` with a non-`thrice_daily` frequency — and `twice_daily` lands there identically to `once_daily`. The `PostFrequency` type in `growth-types.ts` still lists `'twice_daily'`, `DEFAULT_CONFIG` in `subreddit-config.ts` seeds it as the default, and tests in `subreddit-config.test.ts` and `on-app-install.test.ts` assert it as the expected default. Any subreddit stored in Redis with `postFrequency: twice_daily` will silently get once-a-day posting behavior with no error or warning. The remaining scheduler test that seeds `postFrequency: 'twice_daily'` will also continue passing, masking the semantic drift.
